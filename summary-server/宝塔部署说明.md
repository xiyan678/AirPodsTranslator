# 声译 AI 总结：Linux 宝塔部署

接口域名：`ai.duwang.win`。App 请求 `https://ai.duwang.win/v1/summary`。
服务端负责调用百炼 Qwen，用户无需填写 Key；Key 只存服务器 `.env`，不进入 GitHub 或安装包。

## 1. 域名解析与运行环境

在域名 DNS 管理处，把 `ai.duwang.win` 的 A 记录指向这台服务器公网 IP。
宝塔安装 Nginx、Node.js 22 或更新版本。服务器/云平台安全组放行 80、443。
3001 只监听本机，不需要放行。

## 2. 上传代码

在宝塔“文件”中创建 `/www/wwwroot/ear-yi-summary`，上传并解压部署包到这个目录。
确认 `server.mjs`、`package.json` 和 `.env.example` 直接位于目录内，没有多套一层文件夹。
新版包含语音合成和邀请活动模块，需要安装依赖。在终端先运行：

```bash
cd /www/wwwroot/ear-yi-summary
PATH=/www/server/nodejs/v26.13.0/bin:$PATH npm ci --omit=dev --ignore-scripts
```

更新时保留现有 `.env`、`devicecheck.p8`、`data/`；不要覆盖或删除它们。上传包不包含这些私密文件和运行数据。

## 3. 设置百炼 Key

在宝塔文件管理中复制 `.env.example`，副本命名为 `.env`。
编辑 `.env`，在 `DASHSCOPE_API_KEY=` 后填写你自己的 Key。还需按下面的步骤配置设备验证。
默认使用百炼中国站的 `qwen-plus`；如果 Key 属于其他地域，需要对应调整 `QWEN_ENDPOINT` 和可用模型名称。
不要把 `.env` 上传到 GitHub，不要把服务端目录设置成网站静态根目录。

### 配置 Apple DeviceCheck（或使用下方测试连接码方案）

1. 使用**与当前 iPhone 安装包签名相同的 Apple 开发者团队**登录 Apple Developer，在 Certificates, Identifiers & Profiles → Keys 创建启用 DeviceCheck 的密钥，下载 `.p8`。记录 Key ID 和 Team ID。这不是百炼 Key，也不是 `.p12` 证书密码。
2. 把密钥单独上传为 `/www/wwwroot/ear-yi-summary/devicecheck.p8`，不要上传到 GitHub，也不要打进 App。
3. 在 `.env` 填写 `APPLE_TEAM_ID`、`DEVICECHECK_KEY_ID`、`DEVICECHECK_KEY_FILE`。Ad Hoc / App Store 包用 `DEVICECHECK_ENVIRONMENT=production`；Xcode 开发包用 `development`。
4. 终端执行 `chown www:www devicecheck.p8` 和 `chmod 600 devicecheck.p8`，确保服务能读取它。

如果当前证书由第三方提供，需要对应签名团队提供 DeviceCheck 密钥或用自己的团队重新签名。没有这项配置时，可使用本文末尾的测试连接码方案；未启用任何授权方式时，接口会拒绝请求。先配好服务端，再更新 App。不要直接覆盖正在工作的旧服务。

此校验确认来自 Apple 验证的设备凭证，不代表用户登录、订阅校验或完整的 App Attest 应用完整性证明。

## 4. 启动并设置开机运行

在宝塔终端执行：

```bash
cd /www/wwwroot/ear-yi-summary
node --version
bash install-service.sh
```

如果提示找不到 Node 或版本过旧，在宝塔 Node 管理中找到所装版本的 `node` 绝对路径，作为参数运行：

```bash
bash install-service.sh /你的Node安装目录/bin/node
```

脚本会将密钥文件权限设为 600，创建 `ear-yi-summary` 服务，用 `www` 用户运行并开机自启。
如果上传工具把 shell 文件改为 CRLF，先在宝塔编辑器转为 Linux 换行，再运行脚本。
检查本机接口：

```bash
curl http://127.0.0.1:3001/health
```

正常返回 `{"ok":true,"configured":true}`。这只表示服务启动并读到了 Key，不代表 Key 已通过百炼验证。

## 5. 添加域名站点和 HTTPS

宝塔“网站”添加 `ai.duwang.win`，站点根目录使用 `/www/wwwroot/ai.duwang.win`，不创建数据库。
在站点 SSL 设置中申请并启用证书，再启用强制 HTTPS。
将站点 `/` 反向代理到 `http://127.0.0.1:3001`，关闭缓存，读取超时至少 65 秒。
代理必须把 `X-Real-IP` 设置为 `$remote_addr`，保证按真实来源限流。

如果用配置文件方式，可将包中的 `nginx-location.conf` 内容放进该域名的 `server {}` 中，替换原有的 `location / {}`。
不要与宝塔自动创建的同路径代理重复添加。保存前用宝塔的配置检测确认 Nginx 配置有效。

## 6. 验证真实 AI 总结

访问 `https://ai.duwang.win/health` 应返回 `{"ok":true,"configured":true}`，表示百炼和设备验证配置均已读取；不代表两边的凭证已在线验证成功。

匿名 POST 请求现在应返回 401，且不会调用百炼。真实总结需要新版、正确签名的 iPhone App 生成一次性设备凭证：在同传页面打开 AI 总结，检查三组要点。旧 App 不发送设备凭证，不能调用新版接口。

## 7. App 接入

源码已默认设置 `https://ai.duwang.win/v1/summary`，部署完成后重新构建安装即可。
App 设置里的“使用自己的模型 API”关闭或未填 Key 时，都走这个默认服务。
如需改接口地址，可在 Codemagic 添加普通环境变量 `SUMMARY_SERVICE_URL`；不要把百炼 Key 填给 App 构建流程。

## 维护

```bash
systemctl restart ear-yi-summary
systemctl status ear-yi-summary --no-pager
journalctl -u ear-yi-summary -n 50 --no-pager
```

更新服务端代码后重启；修改 `.env` 后也需重启。
内置单 IP 小时限制、全服务每日限制和并发限制，额度可在 `.env` 调整。
小时/每日限流和已使用设备凭证的哈希保存在 `data/limits.json`，服务重启后继续计数。不要删除这个文件来清额度；更新包不包含它。单实例运行，多进程部署需要共享数据库。状态文件损坏时服务会停止启动，先排查并恢复备份，不静默重置。
默认不记录对话正文或 API Key；如自行开启额外请求日志，应避免记录请求正文。

新版更新时保留服务器原有 `.env`、`devicecheck.p8` 和 `data/`，上传代码后重新运行 `bash install-service.sh /www/server/nodejs/v26.13.0/bin/node`，让 systemd 获得 data 目录写权限。


## 安娜语音、新订阅界面与邀请活动

1. 保留原来的 `DASHSCOPE_API_KEY`，在 `.env` 增加：

```dotenv
DASHSCOPE_WORKSPACE_ID=ws-3vtghkxq6gkuap9d
COSYVOICE_MODEL=cosyvoice-v3.5-plus
COSYVOICE_VOICE=cosyvoice-v3.5-plus-bailian-20fde1dbc7b04884862ee1b54a2c128f
APPLE_BUNDLE_ID=app.eggplant1907.jet4469
APPLE_APP_ID=你的AppStoreConnect数字AppleID
APPLE_ROOT_CERT_FILES=certificates/AppleRootCA-G2.cer,certificates/AppleRootCA-G3.cer
REFERRAL_STATE_FILE=data/referrals.json
```

`APPLE_APP_ID` 是 App Store Connect 应用信息中的数字 Apple ID，不是 Team ID、Bundle ID 或 Apple 登录账号。如果正式发布使用其他 Bundle ID，同时更改 `APPLE_BUNDLE_ID`。付费奖励只接受对应正式应用的 Production 交易；Ad Hoc 包、沙盒交易不会假装产生付费奖励。未配置交易核验时仍可使用邀请激活奖励，首次付费奖励暂不能发放。

2. 上传 `speech.mjs`、`referrals.mjs`、`server.mjs`、`device-check.mjs`、`package.json`、`package-lock.json`、`certificates/` 和安装脚本。先安装依赖，再运行：

```bash
bash install-service.sh /www/server/nodejs/v26.13.0/bin/node
curl -sS https://ai.duwang.win/v1/speech/health
```

只有 `configured:true` 表示已读取语音和设备验证配置，实际合成还需在新版 App 中测试。请不要粘贴真实密钥到聊天、GitHub 或 App 构建变量。语音请求使用指定业务空间的专属 WebSocket 域名。无需在服务器安装语音模型或显卡。

3. App Store Connect 创建自动续订订阅商品：`你的BundleID.pro.monthly`、`你的BundleID.pro.yearly`。参考月费 ¥68、年费 ¥498；界面加载后以 StoreKit 实际本地价格为准。点击“兑换码”打开苹果官方兑换窗口，码也必须在 App Store Connect 的优惠码功能中创建。生成邀请码与苹果兑换码是不同入口。

4. 活动接口均为 POST：`/v1/referrals/status`、`generate`、`activate`、`purchase`。需要 App 生成的有效、未使用设备凭证及钥匙串身份。用户激活好友邀请码后双方各得 1 天；被邀请用户首次合规付费订阅，邀请人额外得 3 天。到期时间、人数和奖励累计由服务器持久保存；后续奖励从当前有效期后累加。设备凭证验证失败时不发放奖励。

5. `data/referrals.json` 是奖励账本，务必备份。当前服务仅支持一个 Node 进程；不要用 PM2 cluster 或多副本共享此 JSON 文件。App 在启动、返回前台和打开设置时刷新奖励；断网重启不会凭本地时间伪造新的会员资格。该方案无用户账号，安装身份由设备钥匙串保存，不能当作跨设备账号系统。

6. DeviceCheck 的 bit0 用于标记设备已经领取激活奖励，bit1 不修改。如果同一开发者团队的其他应用已使用 bit0，需要先协调用途。DeviceCheck 是基础防重复手段，不等同完整的 App Attest 防篡改系统。付费奖励发放时验证签名、归属、正式环境、有效期和付费金额并防重；未来需要在退款后收回已发活动奖励时，应进一步接入 App Store Server Notifications，此版不自动追踪后续退款。

Apple 根证书来自 Apple 官方证书颁发机构页面：
`https://www.apple.com/certificateauthority/AppleRootCA-G2.cer`
`https://www.apple.com/certificateauthority/AppleRootCA-G3.cer`

部署前可运行 `npm test` 检查服务逻辑；它不替代真实苹果商品、签名和百炼账号的联调。


### 安娜接口返回 404 时的升级

如果总结 `/health` 正常，但 `/v1/speech/health` 是 404，说明线上服务还没有语音模块。只重新构建 App 无法更新 Linux 服务器。

将新版服务端包解压到现有 `/www/wwwroot/ear-yi-summary`，覆盖包内源文件。保留你已有的 `.env`、`.p8` 和 `data`。在宝塔 root 终端运行：

```bash
cd /www/wwwroot/ear-yi-summary
bash update-anna.sh /www/server/nodejs/v26.13.0/bin/node
```

此脚本备份 `.env`，仅更新指定业务空间、模型和安娜音色三个配置，保留 API Key 和设备验证配置；安装依赖、运行后端测试、重装服务，并检查本机和 HTTPS 语音健康接口。备份也含有密钥，不要分享或上传到 GitHub。`configured:true` 只表示配置已读取，实际音色还需用新版 App 测试。App 至少需要 `829dd79` 版本的源码。服务器语音合成失败时，App 当前会回退到本机系统声音。


## 没有 Apple 团队密钥：个人测试连接码

新版支持服务端授权个人测试设备，无需创建 DeviceCheck `.p8`。配对仅开放安娜语音与默认 AI 总结；邀请奖励接口继续要求原来的 Apple 设备验证，不因配对放宽。

1. 上传最新服务端更新包，保留 `.env`、已有密钥和 `data/`，运行 `bash update-anna.sh /www/server/nodejs/v26.13.0/bin/node`。脚本在 Apple 配置不完整时启用 `CLIENT_PAIRING_ENABLED=1`，安装并重启后会生成一个 12 位连接码，有效期 10 分钟，仅可使用一次。
2. 重新云编译、安装支持“服务连接”的新版 App。在 设置 → 服务连接 输入终端显示的连接码，点击连接。无需把码或 API Key 发到聊天里。
3. 安娜语音和 AI 总结会使用该设备的授权凭证。凭证仅保存在手机钥匙串，服务器只存哈希；默认有效期 90 天，另受设备、IP、全局日请求量及并发限制。百炼 API Key 仍只在服务器。
4. 如连接码过期或需要再配对一台测试设备，在服务器执行（生成后不必重启）：

```bash
cd /www/wwwroot/ear-yi-summary
runuser -u www -- /www/server/nodejs/v26.13.0/bin/node --env-file=.env pair-client.mjs
```

每次生成新码会使上一条未使用的码失效；已配对设备不受影响。若手机收到配对响应后未能存入钥匙串，需要重新生成连接码。不要把连接凭证、连接码文件或 `data/` 放入公开下载目录。

配对文件 `data/client-pairing.json` 和授权账本 `data/client-access.json` 使用单进程本地存储，请备份并保留。个人配对模式证明设备获得过服务器管理员授权，不是 Apple 设备真实性证明，也不是公开注册账号体系。正式面向大量用户发布时需接入账户及订阅授权，不应把管理员生成连接码当成自动注册。
